## 5. 关键决策记录（为什么这么定，避免以后推翻重来）

| # | 决策 | 理由 |
|---|---|---|
| 1 | **开发、测试、部署统一用 PostgreSQL，不用 SQLite** | 容器化后 SQLite 的"省事"前提消失了；两套库的方言差异是最难查的 bug |
| 2 | **坐标一律归一化 `[0,1]`，基准 `ref_modality` 默认 rgb** | 页面缩放不用重算；RGB 和 IR 分辨率不同（1920×1080 vs 640×512），只存一套尺寸会错 |
| 3 | **每帧一行 `frame_results`，包括无目标的帧** | 否则前端分不清"处理过且无目标"和"压根没处理到"，而需求要求区分六种状态 |
| 4 | **`frame_index` = 原始视频帧号**，不是抽帧后序号 | 否则和 `frame_ts_ms` 对不上，也跳不回现场。两者差 `stride` 倍 |
| 5 | **`requested_mode` 和 `actual_mode` 分开存** | 用户可能请求 `auto`，实际跑的是具体模式，且必须能解释为什么 |
| 6 | **枚举用 varchar，不加 CHECK 约束** | 后期加值不用迁移；合法性交给 Pydantic 层 |
| 7 | **检测结果只存模型输出，业务判定放告警表** | 判规则会改（矩形→多边形），写进检测结果就得改历史数据 |
| 8 | **双模态先做结果级融合，特征级后做** | 结果级零训练成本，能保证 12 月有东西可演示 |
| 9 | **LFBNet 只作 SOTA 对照，不复现** | 它用 A100 40GB + ResNet-50 双流 + 200 epochs，6GB 的 4050 无法照搬 |
| 10 | **训练日常用主机 venv，复现用容器** | 容器保环境一致，但 Windows bind mount 的 I/O 会拖慢训练 |
| 11 | **前端在主机跑，不进容器** | Vite HMR 在 Windows bind mount 上要开轮询，反而更慢 |

> 完整推导见 `README.md` §2、§7 和 `docs/database.md` §3。

## 6. 踩过的坑（每条都是今天真实遇到的，别再踩）

### 6.1 `docker` 命令找不到

Docker Desktop 是**按用户安装**的（`C:\Users\susan\AppData\Local\Programs\DockerDesktop`），
装完会写进用户 PATH，但**已打开的终端不会刷新**。

**解法**：关掉终端重开。不需要重启电脑。

### 6.2 构建报 `failed to fetch oauth token`

```
Post "https://auth.docker.io/token": dial tcp 128.242.240.20:443: connectex: ...
```

**原因**：BuildKit 换 token 的连接超时，但 `docker pull` 走守护进程是通的。
表现为"**能 pull、不能 build**"。

**解法一（临时）**：
```powershell
$env:DOCKER_BUILDKIT = "0"
docker compose build api
```
注意只对当前终端窗口有效。

**解法二（正解）**：在阿里云容器镜像服务拿专属加速器地址，
填进 Docker Desktop 的 `Settings → Docker Engine`，`Apply & Restart`。

### 6.3 没配镜像加速器，拉取慢到怀疑人生

`postgres:16-alpine` 单层下载速度在 **0~1MB/分钟** 之间反复卡顿，
420MB 的镜像耗了十几分钟。`python:3.11-slim` 同理。

**建议先手动拉大件**：`docker pull python:3.11-slim`、`docker pull postgres:16-alpine`。

### 6.4 PowerShell 把中文源码写坏

`Set-Content` / `Out-File` 在 **PowerShell 5.1 下默认按 GBK 写文件**。
用它改带中文注释的 `.py`，会变成乱码，报
`SyntaxError: unterminated triple-quoted string literal` 这种看不懂的错。
（今天真踩了，`main.py` 被写坏过一次。）

**解法**：改源码用 VS Code；非要用脚本就显式 `-Encoding utf8`。
排查：`python -c "open('backend/app/main.py','rb').read().decode('utf-8')"`。

### 6.5 `python -m ml.xxx` 在容器里跑不起来

`ml/` 是挂到 `/app/ml`（**不是** `/opt/ml`），靠 `PYTHONPATH=/app` 生效。
如果改挂载位置，这类命令会全部失效。

### 6.6 改了 `.env` 里的数据库密码，连不上了

`POSTGRES_PASSWORD` 只在**数据卷第一次创建时**生效。改了密码但卷里是旧的。

**解法**：
```powershell
docker compose down -v      # ⚠️ 会清空数据库，需重新迁移+建管理员
docker compose up -d
docker compose exec api alembic upgrade head
docker compose exec api python -m app.scripts.seed_admin
```

### 6.7 `docker compose down -v` 是危险命令

会删掉数据卷和库里所有数据。日常停止用 `docker compose stop` 或 `down`（不带 `-v`）。
