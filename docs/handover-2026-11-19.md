### 1.4 后端为前端补的接口

| 接口 | 用途 |
|---|---|
| `POST /api/auth/register` | 注册（**由 `ALLOW_SELF_REGISTER` 控制，默认关闭**） |
| `GET /api/media/{id}/poster` | 视频首帧预览（上传后能立刻画框，不用先跑检测） |
| `GET /api/media/{id}/video` | 原始视频流，**支持 HTTP Range**（拖进度条） |
| `GET /api/detect-tasks/{id}/render` | 导出标注视频，默认 MP4，无 ffmpeg 时退回 WebM |
| `DELETE /api/media/{id}` | 删媒体（级联删任务/区域/告警） |
| CORS | 只放行 5173 / 8000，不用通配符 |

另外 `TaskOut` 带了 `media` 摘要、`AlertOut` 带了 `snapshot_url` + `media_name`
（都是批量查，避免 N+1）。

现在共 **23 个业务接口 + 2 个健康检查**。

### 1.5 容器改造（这轮踩坑最多，结论都写进注释了）

| 改动 | 效果 |
|---|---|
| 去掉 `build-essential` / `libpq-dev` | `psycopg[binary]` 是 wheel，不需要编译器 → **镜像 1.15GB → 813MB** |
| 不 apt 装 ffmpeg | 改用 pip 的 `imageio-ffmpeg`（自带静态 ffmpeg 25MB） |
| apt 源换**阿里云 https** | 直连 deb.debian.org 只有 ~900B/s，代理会 502，阿里云 80 端口 404，**只有 443 稳** |

## 4. 今天修掉的 6 个真 bug（别再踩）

| 现象 | 根因 |
|---|---|
| 上传图片后右侧显示"图片加载失败" | `<img>` 发请求带不了 `Authorization` 头 → 401。改成 fetch + blob + objectURL |
| 没拖鼠标也在画框 | `mousemove` 只判断"有没有矩形"，没判断"鼠标键是否按下"；`mouseup` 又不清空 |
| 画完看不到区域轮廓 | 上一条的连带后果：点保存时鼠标已移到按钮，坐标被夹到画布边缘，存成退化区域被拒 |
| 视频黑屏 + 一直"正在加载" | OpenCV 造的 `mp4v` 视频 **Chromium 解不了**；演示片必须是 H.264 或 WebM |
| 首帧的检测框不显示 | `currentFrame` 初始就是第一帧，用"帧号变了"判断重绘导致首次跳过 |
| 导出视频里区域名是问号 | `cv2.putText` 用 Hershey 字体，**只支持 ASCII**。改用 PIL + 中文字体 |
