# 检测算法：可选实现路线调研（2026-11-20）

> 目的：检测这一块之前是**桩**（StubDetector，按帧号造假框）。
> 这份文档梳理"效果好的实现方式"有哪些、各自代价多少、在我们
> （6GB 显存 / 7 周 / 3 人）的条件下该选哪条。

---

## 1. 先说结论

| 优先级 | 做什么 | 为什么 |
|---|---|---|
| **P0（必做）** | **单模态 YOLO 基线**：热红外单独训一个，可见光单独训一个 | 热红外单模态就能到 AP50 ≈ 79，是**性价比最高的起点**；同时得到论文必需的对照组 |
| **P1（推荐）** | **双流 + 门控/注意力融合**（feature-level） | AP50 能到 79~80，工程量可控，显存够 |
| **P2（差异化）** | **改进"自适应选择"**：把现在的规则改为**光照引导的可学习权重** | 这是项目的题目所在，也是最能体现创新的地方 |
| **P3（慎选）** | LFBNet 式的**频域对齐融合** | 84.6 AP50 是当前最好，但需要 A100 级训练 + 实现复杂，7 周内风险高 |

**一句话**：先把热红外单模态基线做扎实（这一步就能让系统"真的能检测"），
再上双流融合，最后把"自适应"做成可学习、可消融的模块——而不是继续用阈值规则。

---

## 2. 四条技术路线对比

数据都是 **UAV-CB 数据集**（我们要用的那个）上的实测值。

| 路线 | 思路 | 代表工作 | AP50 | AP(0.5:0.95) | 参数量 | 显存友好度 |
|---|---|---|---|---|---|---|
| ① 单模态 | 只用可见光或只用热红外 | RT-DETR | 73.4（可见光）<br>**79.5（热红外）** | 44.2 / 49.2 | 12.0M | ★★★★ |
| ② 朴素融合 | 6 通道拼接 / 像素相加 | YOLOv5s+Add | — | **38.5** | ~7M | ★★★★★ |
| ③ 特征级融合 | 双流提特征 + 注意力/门控融合 | SFDFusion、C2Former | 79.2 / 79.4 | 49.0 / 49.1 | 21.5M / 100.8M | ★★★ |
| ④ 对齐感知融合 | 先对齐再融合（频域 / 隐式偏移） | **LFBNet**、IGIANet | **84.6** / — | **54.4** | 30.2M | ★★ |

### 2.1 关键发现：朴素融合反而更差

注意 ② 的 **38.5** —— 比单模态热红外的 **49.2** 低了 10 个点。

原因是 **UAV-CB 数据集是故意不做像素级配准的**：论文明确说"完美对齐在真实系统里几乎不可能，
保留视差和传感器偏移更真实，也逼着方法去处理模态错位"。

所以**直接把两个模态拼起来（early fusion）会因错位而互相干扰**。
这对我们很重要——决定了融合必须"带对齐意识"，或者干脆在**结果级**融合。

同一篇论文的消融也印证：

| 配置 | AP(0.5:0.95) | 增益 |
|---|---|---|
| YOLOv5s + Add（朴素） | 38.5 | — |
| 只加频域对齐（LFCA） | 47.9 | **+9.4** |
| 只加频域引导空间对齐（FGSA） | 49.3 | **+10.8** |
| 两者都加（LFBNet） | 54.4 | **+15.9** |

**"对齐质量"比"模型容量"更关键**：LFBNet 用 1/3 的算力超过了 100.8M 参数的 C2Former。

## 3. 各路线具体怎么做

### 路线 ①：单模态基线（P0）

最省事，也最该先做。**热红光是主力**：夜暗、逆光、复杂背景下热红外依然稳定。

```bash
# 两份数据各自训练，直接借用 ultralytics 生态
YOLO(rgb).train(data=uavcb_rgb.yaml, imgsz=640)   # 预期 AP50 ≈ 65~73
YOLO(ir ).train(data=uavcb_ir.yaml,  imgsz=640)   # 预期 AP50 ≈ 78~79
```

价值不只是"跑起来"：
- 它是**论文里必须有的对照组**（证明多模态有用）
- 它给出的两个模型，可以被"自适应选择"直接调度
- 只需改 `DETECTOR_BACKEND=ultralytics` + 权重路径，上层不用动

### 路线 ②：朴素融合——只作为消融项，不要当方案

拼接 / 相加 实现最简单，但在**未配准**数据上会掉到 38.5。
**别把精力花在它上面**，但**要在论文里报这个数**，用来衬托后面两种融合的价值。

> 我们代码里现有的 `fusion` 模式是**结果级融合**（两个模型各出框再合并），
> 和这里的"输入级/特征级融合"不是一回事，要分开表述，别混淆。

### 路线 ③：双流 + 门控融合（P1，推荐）

```
RGB ──► backbone ──┐
                   ├── 融合模块（门控 / 通道注意力 / cross-attention）──► neck ──► head
IR  ──► backbone ──┘
```

工程上最友好，因为**两个 backbone 都可用预训练权重**，融合模块只占很小一部分参数。

可选的融合模块（按实现难度排序）：

| 融合方式 | 说明 | 难度 |
|---|---|---|
| 通道拼接 + 1×1 卷积 | 最简，参数少 | ★ |
| **CBAM / SE 门控** | 让网络自己学"哪个模态更可信" | ★★ |
| 跨模态 cross-attention | 效果更好，显存开销大 | ★★★ |
| 双向条件融合 | C2Former 那种，参数爆炸 | ★★★★ |

**推荐先做 SE/CBAM 门控**——参数量几乎不增，且"门控权重"本身就可以可视化，
正好作为"自适应选择"的证据。

### 路线 ④：对齐感知融合（P3，慎选）

LFBNet 的核心是两步，都挺重：

1. **LFCA**：把图像切成 16×16 patch，逐块做 2D FFT，在**局部频域**对齐幅度和相位
   （高频管边缘、低频管能量），再 iFFT 回空间域
2. **FGSA**：把频域差异编码成 6 维引导向量（相位位移方向/强度、高/低频可靠度、频谱一致性），
   驱动**可变形卷积**做空间对齐

效果确实最好（84.6），但：
- 论文在 **A100 40GB、ResNet-50、batch 16、200 epoch** 上训的
- 我们在 4050 6GB 上要把 batch 压到 2~4，训练时间会拉长到数天
- 频域 patch 操作 + 可变形卷积的实现和调试成本高

**结论：7 周内不作为主线**。可以在报告里作为"未来工作"，
或者**只实现 LFCA 的第一步**（幅度归一化 + 相位对齐）作为轻量增强。

## 4. 真正该重点做的：把"自适应选择"做对

题目的核心卖点是**自适应选择**，但这块现在是**规则式的**：

```python
# backend/app/services/selector.py（现状）
if 亮度 < 40 and 红外存在:        → 选 ir
elif 对比度 < 25 or 清晰度 < 100:  → 选 fusion
else:                            → 选 rgb
```

这是工程上的合理兜底，但**作为创新点很薄**：阈值是拍的，没法端到端优化，
也没法证明"它就是最优选择"。

### 4.1 学术界的做法（可直接借鉴）

| 工作 | 机制 | 要点 |
|---|---|---|
| **IGIANet**（AAAI-26） | **光照引导的频域调制**：用全局光照估计，**自适应分配可见光/热红外的融合权重** | 与我们的题目几乎一致，且明确解决"不同光照下模态失衡" |
| GEM-YOLO | **门控多模态融合**，轻量实时 | 适合小显存 |
| SGAFuse | 语义引导 + **动态门控** | 强调"按需融合" |
| MoCTEFuse | **光照门控的专家混合**（MoE） | 用光照当门控信号 |
| RGB-T Detection with Failure Scenarios | 模态缺失场景下的鲁棒性 | 红外缺失时如何退化到可见光 |

### 4.2 我们的实现建议：规则 → 可学习，分两步走

**第一步（低成本，1~2 天）**：保留规则选择，但把它变成**可解释的软权重**，
而不是硬切换：

```python
# 现在的硬选择
mode = selector.pick(image)

# 改成软权重（融合时按权重加权）
w_ir  = sigmoid((40 - brightness) / 10)      # 越暗越信红外
w_rgb = 1 - w_ir
```

论文里就能画一条 **"权重 vs 亮度"曲线**，比"阈值 40"有说服力得多。

**第二步（真正的创新点）**：把权重交给网络学

```
全局光照统计 ──► MLP ──► (w_rgb, w_ir) ──► 加权融合特征
```

或者更简单：**在融合模块里用 SE 门控**，让网络自己学权重，
然后把门控激活值可视化出来，说明"暗环境下红外通道权重确实升高了"。

### 4.3 杀手级实验设计（决定论文成色）

要证明"自适应"有用，必须做这个对照：

| 实验组 | 设置 |
|---|---|
| A | 固定只用可见光 |
| B | 固定只用热红外 |
| C | 固定 6:4 加权融合（不带自适应） |
| D | **我们的自适应选择** |

然后按**光照/时段分组**（白天 / 黄昏 / 夜间 / 逆光）统计 AP50。

**预期的结论**：全天候平均上 D 最好；白天 A 接近 D；夜间 D 显著超过 A。
只要这个趋势出来，"自适应"就站得住——**而且这张分组表本身就是报告里最有说服力的图表**。

## 5. 6GB 显存的现实约束

| 方案 | 640×512 batch | 说明 |
|---|---|---|
| YOLO11n / YOLOv8n 单模态 | 16~32 | 轻松 |
| YOLO11s 单模态 | 8~16 | 推荐起点 |
| 双流 YOLO11s + 门控融合 | **4~8** | 需要 AMP + 梯度累积 |
| ResNet-50 双流 + 注意力融合 | **2~4** | 可行但慢 |
| LFBNet 全量 | 1~2 | 训练周期过长 |

配套技巧：
- `amp=True`（混合精度）基本必开
- 梯度累积补 batch（`accumulate=4` 相当于 batch×4）
- `imgsz` 从 640 降到 512 能省约 35% 显存，小目标受影响但 UAV-CB 目标本就 <5% 面积，需要实测
- 训练前用 `torch.cuda.empty_cache()` + 关掉其他占显存的程序

## 6. 代码落点（现有架构不用改）

我们已经把接口留好了，换模型**只动这三处**：

| 文件 | 现状 | 要做什么 |
|---|---|---|
| `backend/app/services/detector.py` | `StubDetector`（默认）/ `UltralyticsDetector` | 微调 `UltralyticsDetector`，或新增双流实现 |
| `backend/app/services/selector.py` | 规则式阈值 | 改成软权重 / 可学习 |
| `backend/app/services/pipeline.py` | 串起选模态 → 检测 → 侵入判定 | 若上双流融合，融合发生在 detector 内部，pipeline 不动 |

配置也已经就位：

```yaml
DETECTOR_BACKEND: ultralytics
RGB_WEIGHTS: /app/ml/weights/rgb_best.pt
IR_WEIGHTS:  /app/ml/weights/ir_best.pt
```

**所以第一件事不是写模型，是确认数据**——先跑：

```bash
MSYS_NO_PATHCONV=1 docker compose exec -T api \
  python -m ml.datasets.inspect_dataset --root /data/uploads/uavcb
```

看清 UAV-CB 的标注到底是 YOLO txt、COCO json 还是 VOC xml，再决定转换脚本怎么写。

## 7. 七周排期建议

| 周 | 目标 |
|---|---|
| W1（11/20–11/26） | 摸清数据格式、跑通 `prepare_yolo` 转换、训出**热红外单模态基线** |
| W2 | 可见光单模态基线 + 两组对照数据（这样报告就有第一张表） |
| W3–W4 | 双流 + SE/门控融合，目标 AP50 ≥ 80 |
| W5 | **自适应权重**改造（软权重 → 可学习），做 §4.3 的四组对照 |
| W6 | 接进系统（换权重路径）、补跑全链路、写报告图表 |
| W7（1/4–1/10） | 冻结模型、只做集成与答辩材料 |

**风险缓冲**：如果 W3–W4 融合效果不理想，**退回"两个单模态 + 规则/软权重选择"**
也能交付——因为那是我们已有的架构，只是把桩换成真模型。
这个退路要提前跟老师讲清楚。
